# Roadmap

## Worth doing

1. ~~**Tests.**~~ Done: pure logic, handler flows, email builders, AI prompts and validation, the fetchers against canned responses, pickups end to end, league lookups and the odds fallbacks (`make test`, about 99% line coverage). Not covered: live ESPN/Kalshi behavior itself (the fixtures follow the response shapes I know) and the duplicate-player check in the AI pickup validation.
2. ~~**Pick'em failure alerts.**~~ Done: the Lambda publishes to `ComedTopic` itself when a run raises (no extra alarm, so the account stays at the free-tier limit). Async retries are off for the Lambda so one failure sends one email. A timeout or out-of-memory kill dies before the handler can publish, so each run also records a heartbeat in SSM and the `nfl-watchdog` Lambda (schedules a few hours after each expected run) emails if it is missing. An ESPN cookie rejection (HTTP 401/403) emails how to refresh the cookies, at most once a day, instead of failing every run.
3. ~~**Waiver and injury alerts.**~~ Done: `alert` run (Thu 6pm, Sun 6:15am/2pm/6pm and Mon 5:30pm CT, each only when a game kicks off within two hours, emails only if a start/bench change is needed) and `waivers` run (Tuesday 8am CT, emails only if there are pickups).
4. ~~**Bye-week and playoff handling.**~~ Done, as far as I can check before December: the pick'em season-type gate was already right (the NFL postseason is silent). The Thursday pick'em run now also takes Friday and Saturday games (late-season weeks have them; the Sunday run only sees games that haven't started). The fantasy emails go quiet after the league's last scoring period (week 17 here, so week 18 is silent) and, in the playoff weeks (16-17 here), once your team is out of the championship bracket (a consolation game, or absent from a fully drawn bracket). It fails open: missing data or a bracket that isn't drawn yet sends the email. Not verified against live data, since ESPN doesn't draw the playoff schedule until week 15 ends; check the first playoff-week emails. A timeout or out-of-memory kill still only gets caught by the watchdog.

## Nice to have

5. ~~**Pick'em results tracking.**~~ Done: each sent pick sheet is saved in SSM (`/nfl-pickem/picks/<season>-w<week>`); the next Thursday/Sunday run scores last week once its games are final (`/nfl-pickem/results/<season>`) and the email opens with "Week 6: 11/14 correct, 87/105 points. Season ...". Once there are both AI and odds picks it also compares them (flagged per pick). A tie counts as wrong; a week waits (logged) until every picked game is final.
6. **Trade suggestions.** Extend the pickup logic to look at other teams' rosters in the 9-team league.
7. ~~**README and cost notes.**~~ Done: schedule table, SSM parameter table, failure handling, cost estimates, deploy gotchas and test invocations.
8. ~~**CI.**~~ Done, mirrored from TennisTracker: ruff, cfn-lint, pytest, pip-audit, actionlint/zizmor, Dependabot, PR-title check. Merges to main deploy through a `production` environment with a GitHub OIDC role (`deploy-role.yaml`); the PR's checks (`python`, `workflow-lint`) aren't repeated on pushes to main, which deploy directly (a manual run still checks first). The repo is public, so a `dependency-review` job runs on PRs and fails when a PR adds or bumps a dependency with a high-severity advisory (advisory only: not a required check, so it doesn't block a merge).
9. ~~**Smarter alerts.**~~ Done: an alert saves a digest of each move it emails in SSM (`/nfl-pickem/alerts/<season>-w<week>`) and later alerts email only if a move is new. The saved list clears once the lineup needs no change at all, so a problem that comes back alerts again. SSM trouble fails open (the alert still goes out).
10. ~~**Weekly recap.**~~ Done: a `recap` run (Tuesday 7:30am CT, retried Wednesday if a game wasn't final yet; a week is recapped once, tracked in SSM `/nfl-pickem/recap/<season>`) emails how last week went: points scored vs ESPN's projections, the best lineup in hindsight and the points left on the bench, and the matchup result. Free (no AI).
11. ~~**Model choice.**~~ Done: the AI calls default to Claude Sonnet 4.6 (`us.anthropic.claude-sonnet-4-6`). A side-by-side on one week's waiver pickups found it matching Opus 4.6 on the move and the reasoning, while Nova Pro made three generic moves that dropped star players. Opus 4.6 and Nova Pro stay selectable through `ModelId`. Not tried: Opus 5.5 and Sonnet 5.5 (Sonnet 5.5 isn't enabled for the account in Bedrock).
12. ~~**Does the AI review help?**~~ Done: each Thursday/Saturday/Sunday run saves the projection-only lineup and the one emailed after Claude's review; the Tuesday recap scores both by actual points and keeps a season scorecard (`/nfl-pickem/scorecard/<season>`). Alert runs aren't recorded, so a late alert change isn't scored. It judges the lineups emailed, not the one actually set in ESPN. Needs a few weeks of data before it says anything.
13. ~~**Waiver pickups aware of IR.**~~ Done: players in an IR slot are marked as such for Claude, and one invalid move (such as dropping an IR player) is skipped instead of discarding the whole sheet, which silently fell back to the weaker projection-only pickups (seen in week 10).
